# Clio 글감 관리 — 사용 설명서

떠오른 생각을 Discord에 한 줄 던져두면, 원문 그대로 보존하고 비슷한 글감끼리 이어 붙여
나중에 찾아 쓸 수 있게 해주는 시스템입니다.

---

## 먼저 알아두실 세 가지

**1. `글감:` 으로 시작한 메시지만 저장됩니다.**

Clio는 이 채널에서 원래 하던 일(일정 정리, 질문 답변 등)도 계속합니다.
그냥 말을 걸면 평소처럼 대답만 하고 아무것도 기록하지 않습니다.
저장하고 싶을 때만 앞에 `글감:` 을 붙이시면 됩니다.

**2. 번호가 오면 저장된 것, 안 오면 안 된 것입니다.**

저장에 성공하면 Clio가 반드시 `CLIO-0021로 원문을 보존했습니다` 처럼 번호를 알려줍니다.
번호 없이 얼버무리는 답이 오면 **저장되지 않은 것**입니다. 이건 규칙으로 못 박아 두었습니다.
Clio는 실제로 저장이 끝나기 전에는 번호를 말할 수 없습니다.

**3. 교수님이 쓰신 원문은 절대 고쳐지지 않습니다.**

오타, 미완성 문장, 줄바꿈까지 그대로 보관됩니다. Clio가 다듬은 글(정제본)은
원문과 완전히 별도로 저장되며, 화면에서도 `← 교수님 원문` / `← Clio 작성` 으로 구분됩니다.

## 1. 저장하기

### 그냥 새로 저장

```
글감: AI 비서는 모든 것을 기억하는 것보다
무엇을 잊어야 하는지가 더 중요하다
```

여러 줄로 쓰셔도 됩니다. 줄바꿈과 빈 줄까지 그대로 보존됩니다.

Clio의 대답:

```
CLIO-0021로 원문을 보존했습니다.
핵심: 기억하는 능력보다 선택적으로 잊는 능력이 중요하다는 관점
연결 후보: CLIO-0007
현재는 별도 글감으로 두었습니다.
```

> `핵심:` 한 줄은 Clio가 제대로 알아들었는지 확인하시라고 붙이는 것입니다.
> 저장되지 않으며, 이것 때문에 정제본이 만들어지지도 않습니다.

### 어느 글감에 넣을지 이미 아실 때

```
글감 CLIO-0007: 이 논점을 여기 붙인다
```

이렇게 번호를 지정하시면 Clio가 묻지 않고 바로 그 글감에 붙입니다.

### 방금 저장한 것에 덧붙일 때

```
글감+: 아까 그 얘기에 덧붙이면, 잊는 기준을 누가 정하느냐가 문제다
```

### 깜빡하고 그냥 보내셨을 때

```
방금 거 글감으로 저장해
```

바로 앞 메시지를 소급해서 저장합니다.
다만 Clio가 그 원문을 정확히 복원할 수 없으면 저장하지 않고 다시 보내달라고 말씀드립니다.
기억으로 재구성한 문장을 원문인 척 저장하는 일은 하지 않도록 막아 두었습니다.

### 지시어를 쓰는 여러 방법

`글감:` · `아이디어:` · `ㄱ:` 셋 다 똑같이 동작합니다. 편한 것을 쓰시면 됩니다.

⚠️ **반드시 메시지 맨 앞이어야 합니다.** 문장 중간의 "글감:"은 지시어로 보지 않습니다.
그래서 `이 논문은 글감: 이라는 표현을 쓴다` 같은 문장은 저장되지 않습니다.

## 2. 찾아보기

| 하고 싶은 것 | 이렇게 말씀하시면 됩니다 |
|---|---|
| 지금 작업 중인 글감들 | "글감 목록 보여줘" |
| 특정 글감 전체 내용 | "CLIO-0012 보여줘" |
| 주제로 찾기 | "기억 관련 글감 찾아줘" |
| 보관해둔 것들 | "보관된 글감 보여줘" |
| 최근 것만 | "최근 업데이트한 10개 보여줘" |
| 아직 분류 안 된 원문 | "미분류 원문 보여줘" |
| 특정 글감과 이어진 것들 | "CLIO-0007과 연결된 글감 보여줘" |
| 이 원문이 어디서 왔는지 | "원문 21 출처 알려줘" |

목록은 이렇게 보입니다.

```
CLIO-0012 | 2026-08-10 → 2026-08-17
키워드: AI 비서, 기억, 망각
원문: AI 비서는 모든 것을 기억하는 것보다 무엇을 잊어야 하는지를…
수정일: 08-10, 08-12, 08-17
```

검색 결과에는 **왜 이 글감이 나왔는지**도 함께 표시됩니다.

```
CLIO-0007 — 공통어: 기억, 선택
```

## 3. 다듬기

### 정제본 만들기

```
CLIO-0012 정리해줘
```

Clio가 원문들을 읽고 다듬은 글을 만들어 별도로 저장합니다.

```
원문은 그대로 보존하고 정제본 revision 4를 만들었습니다.
변경: '기억 용량'보다 '선택 기준'이 핵심이라는 주장으로 초점을 좁혔습니다.
```

정제본은 **요청하실 때만** 만들어집니다. 원문을 추가한다고 자동으로 갱신되지 않습니다.
그래야 검토하지 않으신 Clio의 해석이 슬그머니 그 글감의 대표 서술이 되는 일을 막을 수 있습니다.

과거 정제본도 전부 남으므로 "3번 정제본 보여줘" 같은 요청이 가능합니다.

### 상태 바꾸기

글감의 상태는 **두 가지가 따로** 있습니다. 섞이지 않습니다.

| 보관 상태 | 뜻 |
|---|---|
| `inbox` | 아직 분류 안 함 |
| `active` | 작업 중 (목록에 기본으로 나옴) |
| `archived` | 당분간 안 쓰지만 보존 (목록에서 숨김, 검색으론 나옴) |

| 발전 단계 | 뜻 |
|---|---|
| `fragment` | 단편 |
| `developed` | 정제본 있음 |
| `outlined` | 개요 |
| `drafted` | 초안 씀 |
| `published` | 발표·출판함 |

그래서 "초안까지 썼지만 잠시 묵혀둔 글감"(archived + drafted),
"출판했지만 계속 발전시키는 글감"(active + published) 같은 게 자연스럽게 표현됩니다.

```
CLIO-0012 보관해줘
CLIO-0012 초안 단계로 바꿔줘
```

### 키워드 손보기

```
CLIO-0012에 '선택' 키워드 추가해줘
```

## 4. 잇고 합치기

```
CLIO-0007이랑 CLIO-0012 비슷한 얘기야, 연결해줘
0003이랑 0007, 0012 합쳐줘
```

합치면 **새 번호가 발급되고 원래 글감 셋은 그대로 남습니다.** 없어지지 않습니다.
새 글감에는 "부모 글감: CLIO-0003, CLIO-0007, CLIO-0012" 가 기록됩니다.

반대로 한 글감에서 일부 원문만 떼어내 새 글감으로 만들 수도 있습니다.

```
CLIO-0012에서 원문 14번만 따로 빼줘
```

## 5. 실수했을 때

```
방금 연결 취소해              ← 직전 작업 하나를 되돌립니다
원문 21을 CLIO-0007로 옮겨줘   ← 잘못 붙은 원문을 다른 글감으로
```

취소해도 **원문 자체는 사라지지 않습니다.** 연결이 풀려 미분류로 돌아갈 뿐입니다.

---

## 6. 지우기

두 단계로 나뉩니다.

**보통의 "지워줘"** → 보관(archived) 처리됩니다. 목록에서 안 보이지만 데이터는 남고
검색하면 나옵니다. 언제든 되돌릴 수 있습니다.

**진짜 삭제** (학생 실명이 들어갔다든지, 민감한 내용을 잘못 올렸을 때)
→ Clio가 무엇이 지워지는지 먼저 보여드리고 **한 번 더 확인**을 받습니다.
확인하시면 본문이 실제로 제거되고, "언제 삭제했다"는 사실만 남습니다.
이건 되돌릴 수 없습니다.

지운 글감의 번호는 **다시 쓰이지 않습니다.** 번호에 빈자리가 생기는 건 정상입니다.

## 7. 데이터는 어디에 있나

```
~/ClioData/
├── ideas.db          ← 실제 데이터베이스
├── attachments/      ← 첨부 이미지·파일 원본
├── exports/          ← Markdown / JSON 내보내기
└── backups/          ← 백업
```

**Dropbox 안에 두지 않았습니다.** 동기화 프로그램이 데이터베이스 파일을 쓰는 도중에
바꿔치기하면 파일이 깨질 수 있기 때문입니다. 대신 **백업만** `~/Dropbox/ClioBackup/`으로
복사됩니다. 백업은 이미 멈춘 사본이라 동기화해도 안전합니다.

```
백업해줘
글감 전부 Markdown으로 내보내줘     ← Obsidian에서 읽으실 수 있습니다
데이터 이상 없는지 확인해줘
```

Markdown 내보내기는 글감 하나당 파일 하나로 나오고, 원문과 정제본이 구분되어 있습니다.

## 8. 처음 몇 주 동안

**Clio가 "이 글감에 넣을까요?"를 자주 물을 겁니다.** 일부러 그렇게 해두었습니다.

비슷한 글감을 Clio가 알아서 이어 붙이는 기능(자동 연결)은 지금 **꺼져 있습니다.**
잘못 이어 붙이면 교수님이 그 글감을 다시 열어보실 때까지 아무도 모르고,
그사이 정제본까지 오염될 수 있습니다. 반면 질문이 좀 많은 건 바로 느껴지고 고치기도 쉽습니다.

그래서 실제 데이터가 쌓이기 전에는 숫자를 추측해서 켜지 않기로 했습니다.

**글감이 50개쯤 모이거나 4주쯤 지나면** 이렇게 말씀해 주세요.

```
자동 연결 임계값 점검해줘
```

그동안 Clio가 제시한 후보와 교수님이 실제로 고르신 결과를 대조해서,
"이 점수 이상이면 물어볼 필요 없이 맞더라" 하는 구간이 있는지 보고드립니다.
근거가 나오면 그때 켭니다.

## 자주 있는 상황

**Q. `글감:` 붙이는 걸 자꾸 까먹습니다.**
바로 다음에 "방금 거 글감으로 저장해"라고 하시면 됩니다.
Discord에 메시지는 남아 있으니 사라지지 않습니다.

**Q. 같은 걸 두 번 보냈습니다.**
자동으로 걸러집니다. "이미 저장된 원문입니다"라고 알려드리고 새로 만들지 않습니다.

**Q. 질문에 답을 안 하고 넘어갔습니다.**
원문은 이미 저장되어 있습니다. 어느 글감에 속할지만 안 정해진 상태로 남고,
"미분류 원문 보여줘"로 나중에 언제든 처리하실 수 있습니다.
Clio가 마음대로 추측해서 붙이지 않습니다.

**Q. 저장했다는 답이 안 왔습니다.**
저장되지 않은 것입니다. 원문을 다시 보내주세요.
Clio는 실패했을 때 교수님이 쓰신 원문을 그대로 되돌려드리도록 되어 있습니다.

**Q. 정제본이 마음에 안 듭니다.**
다시 정리해달라고 하시면 새 revision이 생깁니다. 이전 것도 남아 있으니
"3번으로 되돌려줘"가 가능합니다. 원문은 어느 쪽이든 영향받지 않습니다.
